# @goatnetwork/agentkit

## 0.3.0

### Minor Changes

- ae8aee4: Harden GOAT Flow PayKit cancellation, recovery journals and fresh-payment validation.
  - Broadcast paths prepare and sign separately, checking cancellation before submitting signed bytes. Ethers/viem signers must support transaction signing without sending. Pending broadcast responses are still drained to retain hashes.
  - Validate manifest/token/product, decimal precision, amount limits and memo rules before claiming a new payment key. Retain error causes and unvalidated submission hashes privately. Avoid duplicate journal writes for unchanged status hashes.
  - Sync journal directories after file creation and replacement; report corrupt records as `RECOVERY_REQUIRED`. Compact completed records while preserving replay artifacts. The default memory store caps record count at 10,000, rejects new keys at capacity, and never automatically evicts deduplication keys. Use durable storage for production/restarts.
  - Add the `recovery` risk level for session status recovery and MPP verification. Write-disabled policies block these actions; confirmation policy ranks them with `low`.
  - Native `GoatAdapter.x402CreatePayment` requires explicit `fromAddress` and `idempotencyKey` in both types and runtime, with integer base-unit amounts. Native API base URLs must be HTTPS origins (loopback HTTP is permitted), without a path. Address case variants share an order fingerprint.
  - Missing or unknown payment statuses fail closed; they are no longer defaulted to a payable `created` state. Native unknown statuses report `ADAPTER_REQUEST_FAILED`. Signature acknowledgement validation remains `{ status: 'ok', order_id: <matching ID> }`.
  - CLI module-load failures include startup diagnostics; safe local validation errors remain actionable without printing authenticated server error bodies.
  - Extend separate preparation/signing/broadcast to core native/ERC-20 transfers and the legacy EVM payer adapter. Preserve accepted hashes on confirmation cancellation/errors. Built-in wallets checkpoint the deterministic `signedTxHash` before submission; MPP recovery can verify it after an ambiguous RPC response.
  - Retry failed background journal checkpoints before subsequent MPP verification. Publish fully written claims atomically so failed initial writes do not consume operation keys. Stop reopening existing ancestors during initialization; provision the state directory before concurrent startup. Windows defaults to file durability, explicitly without directory-entry power-loss guarantees; directory durability remains available as a required mode.
  - SDK timeout/abort results expose a non-serialized `settled` promise for final recovery data. The CLI uses that API and exits promptly when chain detection is interrupted. Consolidate cancellation helpers in core.
  - Classify journal I/O and malformed server proofs as adapter failures, and malformed PayKit links/native order input as input errors. Normalize payment symbol case and surrounding whitespace for fingerprints, while preserving decimal spelling beyond trimming. Allow a supplied session ID when the matching journal has no known ID, retaining its chain/token checks.
  - Extend split signing/submission to core approvals, contract writes and deployments. Unsupported raw signing reports `WALLET_SIGN_FAILED` with migration guidance; JSON-RPC wallets must support `signTransaction` or use a local signer. Read-only calls are unchanged. This is a compatibility change in the 0.x minor release.
  - Hold runtime idempotency locks until actual execution settlement after abort/timeout, and cache validated late successes. Pending attempts are not retried concurrently. Existing store TTL limits still apply.
  - After a known MPP broadcast, retry a failed journal checkpoint once and allow verification to continue despite persistent storage failure. If receipt persistence fails, retain the verified receipt and storage diagnostic in private recovery data.
  - Replay completed x402 payments without a live chain RPC. Classify remote response mismatches as adapter failures and share integer-wei/hash validators and CLI action metadata.
  - Print cancellation guidance on first Ctrl-C; a second Ctrl-C force exits with code 130 while retaining the pre-submission signed hash on disk for recovery.
  - Allow matching `prepared` x402, card and MPP reservations with no request evidence to retry safely after storage repair. A separate atomic request claim elects one sender; the x402 claim contains the exact session POST body for status recovery if the primary checkpoint failed. This uses two store records per intent. `requesting` records without evidence remain blocked for reconciliation.
  - Preserve unsaved x402 results, card checkout links and verified MPP receipts in a private emergency CLI journal, exposing its location and the persistence diagnostic. Retrieve MPP receipts through `resume-mpp`, and x402/card results by replaying against the emergency state directory. If emergency storage also fails, return the sole result with explicit guidance instead of silently redacting and discarding it.
  - Report late runtime successes through redacted success hooks/logs and metrics, marked `afterInterruption` only after an interrupted result has been returned to the caller; success observed during retry backoff is a normal success. Document that non-cooperative actions retain their idempotency lock until settlement or TTL expiry (default 3,600 seconds), while `settled` itself can remain pending indefinitely.
  - Audit plugin cancellation forwarding: built-in wallet writes and HTTP actions pass the signal through. Wallet reads and typed-data/auth signing interfaces, giftcard cache/Redis calls and shared authentication waits remain uncancellable and can delay settlement, including during write-action preflight. BitVM2 deposit/withdraw/status are in-process placeholders. Document these limits and the intentional draining of raw broadcasts and recovery writes.
  - Merge wallet error recovery with matching action checkpoints to preserve operation identity and signed evidence. Read viem's bound account locally, wrap MPP payer-read failures, classify invalid manifest terms as adapter errors, and retain cancellation supplied via wallet call options.
  - Define the runtime as the action invocation boundary: reuse one successful input parse and remove the extra PayKit execute-wrapper parse. CLI preview passes raw input to the runtime instead of transforming parsed output again.
  - Restore retries for cooperative timeouts that settle with failure during retry backoff. Unfinished attempts and operations with recovery evidence are not retried. A validated success observed during backoff returns success without error hooks or duplicate latency metrics.
  - Check the MPP signer provider chain before reserving a new key. Treat a retried completion checkpoint as success without retaining a stale persistence diagnostic. Reuse existing intent lookups before claiming new ones.
  - Report durable late CLI completion as success with normal result redaction; omit undefined recovery fields and empty diagnostic suffixes. ### Patch Changes

- ae8aee4: Correct the GOAT Testnet3 (`goat-testnet`, chain 48816) ERC-8004 registry pairing.
  The default Identity Registry changes from `0x556089008Fc0a60cD09390Eca93477ca254A5522`
  (used in versions 0.1.2–0.2.3) to `0x54B8d8E2455946f2A5B8982283f2359812e815ce`,
  the Identity Registry paired with the unchanged Reputation Registry
  `0xd9140951d8aE6E5F625a02F5908535e16e3af964`. Mainnet addresses, ABIs and action arguments are unchanged.

  Existing registrations are not migrated. An agentId is scoped to its registry:
  the same number in the new registry may identify another agent or no agent.
  Do not reuse an old agentId for feedback or metadata operations through the updated
  defaults. Keep old registrations associated with their original registry, and
  register in the new registry to obtain the agentId for the corrected pair.
  New registration files must use
  `eip155:48816:0x54B8d8E2455946f2A5B8982283f2359812e815ce` as `agentRegistry`.

## 0.2.3

### Patch Changes

- 126ea25: fix: point GoatAdapter x402 payment endpoints at the GOAT Flow API domains

  The GoatX402 API was renamed to GOAT Flow and moved domains. `GoatAdapter` now
  selects its base URL per network — `https://flow-api.goat.network` for
  goat-mainnet and `https://flow-api.testnet3.goat.network` for goat-testnet —
  instead of the retired `https://api.goatx402.com`. The `GOAT_X402_BASE_URL`
  override still takes precedence and now has trailing slashes normalized so
  `${base}/api/v1/...` never produces a double slash. Env var names, request
  paths, and the HMAC signing contract are unchanged.
