# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Agentkit is a plugin-based action execution SDK for integrating with Goat Network. It provides a runtime that orchestrates action execution with policy gates, schema validation, idempotency caching, retries, and Prometheus metrics. The README and docs are in Chinese; code and comments are in English.

## Commands

```bash
# Run integration tests (vitest)
pnpm run test:integration

# Run examples
pnpm run example:minimal        # Full x402 + BitVM2 action demo
pnpm run example:error-path     # Error handling paths
pnpm run example:runtime-store  # Idempotency store (memory/redis)
pnpm run example:metrics        # Prometheus metrics endpoint
pnpm run example:export-tools   # Tool manifest export
pnpm run example:x402-eip712    # EIP-712 payment signature flow
```

ESLint and Prettier are configured. TypeScript is compiled via `tsx` (runtime) and `typescript` (type checking).

```bash
# Lint source files
pnpm run lint

# Format source files
pnpm run format

# Check formatting without writing
pnpm run format:check
```

## Architecture

### 4-Layer Structure

1. **Core** (`core/`) — Runtime engine, policy engine, error types, metrics, logging
2. **Plugins** (`plugins/`) — Feature modules that define actions (see Plugin Inventory below)
3. **Adapters** (`adapters/`) — AI framework integrations (OpenAI function calling, LangChain tools, MCP, Vercel AI SDK, OpenAI Agents SDK)
4. **Providers** (`providers/`) — Action registry and tool manifest generation (Zod → JSON Schema)

Supporting directories: `networks/` (Goat chain adapter), `examples/`, `tests/integration/`, `docs/`, `bin/` (end-user CLI entry points — `agentkit-gns`, `agentkit-giftcard`, plus `_lib/` shared helpers), `packages/create-goat-agent/` (project scaffolder CLI).

### Key Runtime Flow

`ExecutionRuntime.execute(actionName, input, opts)` is the central orchestrator:

1. Schema validation (Zod or JSON Schema fallback)
2. Policy engine evaluation (network allowlist, risk level confirmation gates, write-op enable)
3. Idempotency cache check (TTL-based, in-memory or Redis)
4. Action handler invocation with retries (exponential backoff)
5. Prometheus metrics recording (counters + histograms, labeled by action/error)
6. Structured JSON logging

### Action Definition Pattern

Actions implement the `Action` interface from `core/schema/action.ts` with:

- `name`: dotted identifier (e.g., `goat.x402.payment.create`)
- `inputSchema` / `outputSchema`: Zod schemas
- `riskLevel`: `read | low | medium | high` (high requires explicit confirmation)
- `handler(input, context)`: async execution logic

### Adapter Pattern

External integrations use adapter interfaces with swappable implementations:

- `MerchantGatewayAdapter` → `HttpMerchantGatewayAdapter` (production) / mock (tests)
- `PayerWalletAdapter` → `EvmPayerWalletAdapter` (ethers.js) / `NoopPayerWalletAdapter` (dev)
- `GoatAdapter` → Goat chain RPC + HMAC-SHA256 merchant-core signing

### Error Handling

All errors flow through `AgentkitRuntimeError` with typed codes: `INVALID_INPUT`, `POLICY_BLOCKED`, `ACTION_NOT_FOUND`, `ADAPTER_REQUEST_FAILED`, `WALLET_SIGN_FAILED`, `WALLET_TRANSFER_FAILED`, `TIMEOUT`, `INTERNAL_ERROR`.

### WalletProvider

`core/wallet/wallet-provider.ts` defines the interface; three implementations exist:

- `EvmWalletProvider` — production (ethers.js Signer + Provider); also exposes `getLatestBlockTimestamp()` for on-chain readiness checks (used by `gns.wait_for_commitment`)
- `ViemWalletProvider` — production alternative (viem WalletClient + PublicClient)
- `NoopWalletProvider` — dev/test mock; defaults `getChainId()` to `48816` (GOAT Testnet3)

`writeContract` supports an optional `value?: string` parameter for payable contract calls (used by `bridge.withdraw`). `deployContract` deploys contracts on-chain given ABI + bytecode. All three providers implement an optional `getChainId()` so chain-bound actions (`giftcard.pay_order`, `gns.x402.pay_order`) can verify the wallet is on the expected source chain and refuse to broadcast on mismatch.

### ExecutionHooks

The runtime supports optional `ExecutionHooks` for analytics/observability callbacks:

- `onActionStart(event)` — fired at each attempt start
- `onActionSuccess(event)` — fired on success
- `onActionError(event)` — fired on final retry exhaustion
- `onPolicyBlocked(event)` — fired when policy denies

Pass hooks via `ExecutionConfig.hooks` when constructing `ExecutionRuntime`.

### Token Registry

`networks/goat/tokens.ts` provides a centralized symbol→address mapping for Goat predeployed contracts (`WGBTC`, `GOAT`, `BRIDGE`, `BITCOIN`). The `wallet.resolve_token` action exposes this to agents.

### Environment Variables

See `.env.example` for full list. Key variables:

- `AGENTKIT_IDEMPOTENCY_MODE` — `memory` (default) or `redis`
- `AGENTKIT_REDIS_URL` — Redis connection when mode=redis (also used by `Eip712AuthSigner` for single-flight auth-token issuance in the giftcard plugin)
- `AGENTKIT_METRICS_PORT` — Prometheus port (default 9464)
- `MERCHANT_API_BASE_URL` / `MERCHANT_API_KEY` — Merchant gateway config (x402 payment flow)
- `MERCHANT_PORTAL_BASE_URL` — x402 Merchant Portal API base URL (default: `http://localhost:8080`)
- `GOAT_MAINNET_RPC_URL` / `GOAT_TESTNET_RPC_URL` — Goat chain RPC endpoints
- `GOAT_PRIVATE_KEY` — wallet key consumed by `bin/_lib/wallet-from-env.ts` for the end-user CLIs
- `GNS_API_BASE_URL` — GOAT Name Service backend (default `https://gns-api.goat.network/api`)
- `GIFTCARD_API_BASE_URL` — Giftcard backend (default `https://giftcard-api.goat.network`); also `GIFTCARD_AUTH_DOMAIN_{NAME,VERSION,CHAIN_ID}` for the EIP-712 auth domain
- `DEMO_MOCK` — when `true`, the `agentkit-giftcard` CLI may use `NoopWalletProvider`; otherwise a real signer is required for `pay_order`

### CLIs

Two distinct CLI surfaces ship from this repo:

**1. Project scaffolder — `create-goat-agent`**

`packages/create-goat-agent/` is an independent npm package that scaffolds new agent projects. Three presets:

- **minimal** — wallet plugin only (10 actions)
- **defi** — wallet + wgbtc + bridge + bitcoin (27 actions)
- **full** — all 15 plugins (118 actions)

Published usage: `npm create goat-agent`. Local dev usage:

```bash
pnpm --filter create-goat-agent run build
node packages/create-goat-agent/dist/index.js
```

The `generateProject()` function is exported for testing and library reuse.

**2. End-user CLIs — `bin/`**

Shipped as binaries on the main `@goatnetwork/agentkit` package:

- `agentkit-gns` (`bin/gns.mjs`) — register / renew / lookup `.goat` names. Supports `--reveal-secrets` (the `commit` action redacts the 32-byte secret by default; `print-secret` emits it under the flag). Region selection, env-driven wallet via `GOAT_PRIVATE_KEY`, and a `doctor` subcommand for env diagnostics. The `x402-register` subcommand additionally supports `--wait-timeout <sec>` (default `180`) and `--poll-interval <sec>` (default `10`) for the `waitForCommitment` polling window, and runs an `api.x402Config()` preflight to validate the `(--pay-chain, --pay-token, --pay-token-contract)` trio against the merchant config before any GOAT-chain spend (fails `USER_INPUT` early on mismatch).
- `agentkit-giftcard` (`bin/giftcard.mjs`) — browse brands, place orders, pay cross-chain (USDC/USDT on Polygon / Base / Arbitrum / Optimism / BSC / Metis), poll for fulfillment. Hard-refuses `NoopWalletProvider` for real payments outside `DEMO_MOCK=true`.

Shared helpers live in `bin/_lib/` (`wallet-from-env.ts`, `regions.ts`, `confirmations.ts`, `doctor.ts`, `output.ts`, `command-runner.ts`).

### Dependency overrides

`pnpm-workspace.yaml` pins `overrides.ws: ^8.20.1` (also mirrored in `package.json` `pnpm.overrides` for legacy pnpm) to clear advisory **GHSA-58qx-3vcg-4xpx** (`ws` uninitialized-memory disclosure) reaching this repo via `ethers@6.16.0 → ws@8.17.1` and `viem@2.46.3 → ws@8.18.3` / `viem → isows → ws`. Default agentkit usage (HTTP RPC via `EvmWalletProvider` / `ViemWalletProvider`) does not exercise `ws`; the override is defense-in-depth for agents that wire up a WebSocket RPC transport. The override only affects this repo's lockfile — downstream npm consumers of `@goatnetwork/agentkit` must mirror the override in their own root `package.json` or wait for upstream `ethers` / `viem` to bump `ws` themselves.
